# 门锁 ↔ WiFi 模块 配网（蓝牙绑定）对接说明

版本：**v1.0**（2026-10-19）
背景：门锁进入配网模式后发 `0x62`，但 WiFi 现在收到就立刻回 `0xE2`（只是 ACK），门锁无法区分"收到请求"和"蓝牙绑定成功"。本版新增 `0x65`，由 WiFi 在**蓝牙绑定完成**时主动下发，门锁收到后播报并退出配网。

---

## 1. 流程

```
门锁(进入配网模式) → WiFi : 0x62 入网请求（空 payload）        (门锁 300ms×2 重传)
WiFi → 门锁 : 0xE2 ACK（立即回，表示"已开始绑定流程"）
        … 用户用 APP/蓝牙 完成绑定 …
WiFi → 门锁 : 0x65 [0]  绑定成功   /   0x65 [1]  绑定失败      (WiFi 300ms×2 重传)
门锁 → WiFi : 0xE5 ACK
门锁：播报"配网成功"（或"配网失败"）+ 声光提示 + 退出配网模式
```

---

## 2. 命令表

| 命令 | 方向 | payload | 说明 |
|---|---|---|---|
| `0x62` 入网请求 | 门锁 → WiFi | 空 | 请求开始配网；WiFi 收到重复包直接忽略 |
| `0xE2` 入网 ACK | WiFi → 门锁 | 空 | **必须立即回**（门锁 300ms 超时重传） |
| **`0x65` 入网结果** | **WiFi → 门锁** | **1 字节：`0`=成功 / `1`=失败** | **绑定完成时下发** |
| `0xE5` 入网结果 ACK | 门锁 → WiFi | 空 | 门锁收到 `0x65` 后应答 |
| `0x63` 蓝牙 MAC | 门锁 → WiFi | 空 | 可选，应答 `0xE3` |
| `0x64` 蓝牙版本 | 门锁 → WiFi | 空 | 可选，应答 `0xE4` |

> `0x62`/`0x65` 都是最高位=0 的请求帧，走《串口ACK重传对接说明》的通用规则。
> `0xE2`/`0xE5` 是 ACK（最高位=1），本身不再被应答、不进重传。

---

## 3. WiFi 侧改动（关键）

### 3.1 保持 `0x62 → 0xE2` 立即应答

收到 `0x62` 立刻回 `0xE2`，**不要延迟到绑定成功**。原因是门锁只等 300ms（重传 2 次），延迟会触发无意义重传。

### 3.2 在"蓝牙绑定成功"处发 `0x65`

判定点（WiFi 日志实测）：

```
[1792400631.740] W/KIOT_HEX  (0470) recv binding-req          ← APP 发来绑定请求
[1792400631.761] I/EEPROM    (0918) ee_write_pre              ← 写绑定信息
[1792400631.788] W/BLE_CONFIG (0051) ble pairing successful   ← ★ 绑定成功
```

**请在打印 `ble pairing successful` 的位置（`ble_config.c` 第 51 行附近）之后，调用串口发送 `0x65`，payload = `[0]`。**

### 3.3 绑定失败

若 SDK 有明确的失败回调（`BLE_CONFIG` 模块的失败分支），发 `0x65 [1]`。
没有明确失败回调时**可以不发**：门锁 60 秒后自动退出配网（静默，不播报失败）。

### 3.4 发送侧规则

- 等 `0xE5`，超时 **300ms**，最多重传 **2 次**
- 重传原样重发（sn、payload 不变）
- 超时按失败处理（打日志即可，门锁侧会走 60 秒超时）

---

## 4. 门锁侧行为（已实现）

| 收到 | 行为 |
|---|---|
| `0xE2` | **只清重传，不播报**（它只是 ACK） |
| `0x65 [0]` | 播"配网成功" + 绿灯 + **退出配网并回到待机(idle)**，同时重置待机计时保持唤醒 |
| `0x65 [1]` | 播"配网失败" + 红灯闪 + 退出配网并回到待机 |
| 60 秒无 `0x65` | 静默退出配网（不播报失败） |
| 不在配网流程中收到 `0x65` | 只回 `0xE5`，不动作（防重复包/迟到包） |

实现位置：

| 项 | 文件 |
|---|---|
| `0x65` handler | `protocol/handler/uart_protocol_join_net_result.c` |
| 播报/灯效 | `module/module_hmi/module_hmi.c`（`HMI_STATE_JOIN_NET_SUCCESS` / `HMI_STATE_JOIN_NET_FAIL`） |
| 配网入口 | `fsm/state/fsm_state_idle.c`、`fsm_state_verify_admin.c`（发 `0x62`） |
| 回待机 | `fsm_state_idle.c` / `fsm_state_sleep.c`（`EVENT_RESULT_JOIN_NET_DONE`） |

> **回待机后保持唤醒约 10 秒**（重置 `WORK_TIME_OUT_VAULE`），留给 WiFi 同步
> 用户表（`0x08`/`0x01`）、开锁记录（`0x09`）、属性（`0x16` 等）。
> 若同步数据较多、预计超过 10 秒，请在 10 秒内让 WiFi 继续发送，或提前告知我们把该值调大。

## 5. 加密

`0x65` 属于**普通命令**，与其它业务帧一致：

- 发送：`enc=1`，`key = random ^ K_L`
- 接收：门锁用 `K_L` 解密后校验 `checksum2`
- ACK `0xE5` 同样加密（payload 为空，`checksum2` 恒为 0，密钥错也能通过）

> 详见《串口加密对接说明 v1.3》。若 WiFi 侧暂未实现加密，门锁也能收 `enc=0` 的 `0x65`（明文兼容）。

## 6. 验证方法

| 场景 | 预期 |
|---|---|
| 正常配网 | 门锁发 `0x62` → WiFi 回 `0xE2` → APP 绑定 → WiFi 发 `0x65 [0]` → 门锁回 `0xE5` → 播报"配网成功" + 绿灯，配网照明/闪灯停止 |
| 不绑定，等 60 秒 | 门锁静默退出配网，无"失败"播报 |
| 绑定失败 | WiFi 发 `0x65 [1]` → 门锁播"配网失败" + 红灯 |
| 重复 `0x65` | 门锁只应答 `0xE5`，不重复播报 |

**门锁日志观察点**：

```
[uart rx] cmd=0x62 …（门锁发出）
[uart rx] cmd=0x65, sn=…, len=1 …
（msg_protocol）tx cmd=0xE5 …
（hmi）播报 Network_pairing_successful
```

**WiFi 日志观察点**：`ble pairing successful` 之后应紧跟一条 `uart tx, cmd=65`。

---

## 7. 备注

- 门锁配网超时：**60 秒**（`JOIN_NET_TIMEOUT`）
- 门锁进入配网时会播报"已进入配网状态"并蓝灯闪烁（1 秒 1 次）
- 收到 `0x65` 后停止闪烁并允许休眠，不需要 WiFi 再发其它命令
- 如果以后需要"重新配网"，APP 触发后 WiFi 再发一次 `0x65` 即可
