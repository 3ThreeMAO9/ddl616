# 门锁 ↔ WiFi 模块 时间同步对接说明

**版本**：v1.0（2026-10-20，文字精简，协议内容未变）

**背景**：门锁 RTC 上电后从编译时间（2026-01-01）起算，需由 WiFi 提供真实时间；否则开锁记录、用户表时间戳全部失效。

---

## 1. 总体设计

**以门锁主动查询 `0x67` 为主**：

- WiFi 的 `0x66` 只在「首次拿到服务器时间」或「时间/时区发生变化」时下发一次，稳态下**不会重复下发**
- 门锁按固定节奏主动查询，`0x67` **同时充当心跳**（保活 + 对时，一条命令完成）

| 场景 | 依赖 |
|---|---|
| WiFi 首次联网拿到时间 | `0x66` 下发（一次性，可选） |
| 门锁上电 / 休眠唤醒 | **门锁主动发 `0x67`** |
| 稳态运行 | 心跳节奏 `0x67` |

---

## 2. 接口定义

### 2.1 命令表

| 命令 | 方向 | payload | 应答 |
|---|---|---|---|
| `0x66` 时间下发 | WiFi → 门锁 | 8 字节（见 2.2） | `0xE6`（空） |
| `0x67` 时间查询 | 门锁 → WiFi | 空 | `0xE7` + 8 字节；**空 `0xE7` = 暂无有效时间** |

### 2.2 时间 payload（8 字节，小端）

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 4 | `timestamp`：Unix 秒，**UTC** |
| 4 | 4 | `tz_offset`：时区偏移，**秒**，东正西负（`28800` = UTC+8） |

`0x66` 与 `0xE7` 使用同一格式。

### 2.3 通用规则

| 项 | 规则 |
|---|---|
| 帧类型 | `0x66`/`0x67` 为普通请求帧（最高位 0）；`0xE6`/`0xE7` 为 ACK（最高位 1，不再被应答） |
| 重传 | 300 ms × 2 次（与其它请求一致） |
| 加密 | 属普通命令：`enc=1`，`key = random ^ K_L`（详见《串口加密对接说明 v1.3》） |
| 命令号占用 | `0x65` 之后的空闲位，与 `0x63`/`0x64` 无冲突 |

## 3. 对接流程

### 3.1 门锁侧时序

```
上电 / 休眠唤醒
  → 心跳计时到期（上电 3s；唤醒时置为"立即到期"）
  → 发 0x67 ──→ WiFi 回 0xE7 + 8 字节
       ├─ 合法 → 写 RTC
       └─ 空包 / 非法 → 保持原时间
  → 收到 0xE7（有效帧）→ 心跳计时重置 3s
  → 3s 内无新的有效帧 → 再发一包（循环）
```

**节奏**：串口静默 3 秒发一次 `0x67`；期间收到任何有效帧都会重置计时。

### 3.2 WiFi 侧需实现

1. **收到 `0x67` → 回 `0xE7` + 8 字节时间**；本机无有效时间时回**空 `0xE7`**
2. 蓝牙/联网首次拿到服务器时间时，可发一次 `0x66`（非必须，门锁会自己查）
3. 不要把 `0x67` 当作业务请求做超时告警 —— 它本身就是心跳

---

## 4. 异常处理

| 场景 | 处理 |
|---|---|
| `0xE7` 为**空包** | 视为"对端暂无有效时间"，**保持原时间**（不可当成 0 / 1970），3 秒后重试 |
| `0xE7` 时间非法（`timestamp < 1767225600` 即 2026-01-01，或 `|tz_offset| > 14 小时`） | 丢弃不用，保持原时间，3 秒后重试 |
| `0x67` 无应答 | 按 300 ms × 2 重传后放弃，等下一轮心跳（不设次数上限，随休眠自然停止） |
| `K_L` 尚未同步 | WiFi 会丢弃 `0x67` 不回 `0xE7`；密钥同步完成后自动恢复 |
| `0x66` 重传（内容相同） | 幂等，重复设置时间无副作用 |
| 掉电重启 | RTC 无电池备份，上电后自动重新查询 |

## 5. 门锁侧实现（已实现）

| 项 | 说明 |
|---|---|
| `0x66` / `0xE7` 接收 | `protocol/handler/uart_protocol_time.c`：解析 8 字节 → 校验 → `hal_set_rtc_time()` |
| `0x67` 发送 | `uart_msg_time_query()`，走正常发送队列 |
| 时区换算 | `tz_offset ÷ 900` = `hal_rtc` 的 `time_zone`（15 分钟单位，+8 区 = 32） |
| 休眠影响 | 发送 `0x67` 不重置休眠计时；`0xE7` 是 ACK，也不重置 |

## 6. 联调验证

| 侧 | 观察日志 |
|---|---|
| 门锁 | `[uart tx] cmd=0x67`（每 3 秒一次，或唤醒后立即一条） |
| 门锁 | `(up_time) time synced: utc=... tz=...` |
| 门锁 | `(timestamp) time: ...` 变为当前真实时间 |
| WiFi | `time query from mcu -> reply timestamp=..., tz_offset=...` / `uart tx, cmd=E7` |

**验收标准**：门锁时间正确后，`0x09` 查询开锁记录不再出现 `no record hit (newest is older than base)`。

---

## 7. 已知限制

| 项 | 说明 |
|---|---|
| 仅门锁侧校验 | 门锁会拒绝 2026 年之前的时间，WiFi 侧无需额外处理 |
| 唤醒即查询 | 频繁唤醒（如 WDT 定时唤醒）会让总线上多一些 `0x67`/`0xE7` 往返，属正常 |
| 加密依赖 | 未完成 `K_L` 同步时无法对时，但会随密钥同步自动恢复 |
