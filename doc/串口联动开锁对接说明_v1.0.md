# 门锁 ↔ WiFi 模块 联动开锁（4 位配对码）对接说明

**版本**：v1.2（2026-11-06）　**门锁侧已实现，等 WiFi/背板适配**

---

## 1. 用途

两台门锁（A 锁、B 锁）通过各自的 WiFi 模块（下称背板）完成"联动开锁"配对/退出：

- **A 锁**进入"创建联动"菜单 → 输入 **4 位 PIN 码** → 下发 `0x6A` 给背板 → 背板回 `0xEA`（指令接收是否正常）→ A 锁等待 B 锁加入
- **B 锁**进入"加入联动"菜单 → 输入 **与 A 锁相同**的 4 位 PIN 码 → 下发 `0x6B` 给背板 → 背板回 `0xEB`（指令接收是否正常）→ B 锁等待配对结果
- B 加入成功 → **B 的背板上报 `0x6C`（role=1）给 B 锁前板** → B 锁播"设置成功"
- A 的背板感知 B 加入成功 → **A 的背板上报 `0x6C`（role=0）给 A 锁前板** → A 锁播"设置成功"
- **任意锁**进入"退出联动"菜单 → 按 OK 确认 → 下发 `0x6D` 给背板 → 背板回 `0xED` → 退出完成后背板上报 `0x6C`（role=2）→ 门锁播"设置成功"

> A 锁、B 锁烧录的是**同一套固件**，不区分主从；角色只由"用户进了哪个菜单"决定，协议里用 `role` 字段告知背板。

## 2. 命令定义

| 命令 | 方向 | payload | 应答 |
|---|---|---|---|
| **`0x6A`** 创建联动 | **门锁 → 背板** | 4 字节 PIN（见 2.1） | **`0xEA`** + 1 字节 status |
| **`0x6B`** 加入联动 | **门锁 → 背板** | 4 字节 PIN（见 2.1） | **`0xEB`** + 1 字节 status |
| **`0x6D`** 退出联动 | **门锁 → 背板** | 无（空包） | **`0xED`** + 1 字节 status |
| **`0x6C`** 结果上报（配对/退出） | **背板 → 门锁** | 2 字节：`role` + `result`（见 2.3） | **`0xEC`**（空包） |
| **`0x6E`** 联动开锁执行 | **背板 → 门锁** | 无（空包） | **`0xEE`**（空包） |

> ACK 命令字沿用通用规则：`ACK = 命令字 | 0x80`。
> 所有命令 `enc=1`，`key = random ^ K_L`（与其它串口命令一致）。

### 2.1 `0x6A` / `0x6B` payload

| 偏移 | 长度 | 内容 | 说明 |
|---|---|---|---|
| 0 | 4 | PIN 码 | 每字节 **0~9**（数字值，**不是 ASCII `'0'~'9'`**） |

示例：PIN `1234` → `01 02 03 04`

### 2.2 `0xEA` / `0xEB` / `0xED` payload（指令接收正常与否）

| 值 | 含义 | 门锁行为 |
|---|---|---|
| `0x00` | 指令接收正常，已开始处理 | 继续等待 `0x6C`（界面播"配对中请稍候"） |
| 其它 / 空包 | 指令异常（PIN 格式错、已在配对中、无网络、未配对就退出…） | 立即播"设置失败"，退出流程 |

> **背板收到 `0x6A`/`0x6B`/`0x6D` 后必须立刻回 `0xEA`/`0xEB`/`0xED`**；不回 = 门锁 1 秒后判失败。

### 2.3 `0x6C` payload（结果上报）

| 偏移 | 字段 | 取值 |
|---|---|---|
| 0 | `role` | `0`=创建方（A 锁）；`1`=加入方（B 锁）；`2`=退出联动 |
| 1 | `result` | `0`=成功；`1`=失败 |

示例：A 锁创建成功 → `00 00`；B 锁加入成功 → `01 00`；A 锁退出成功 → `02 00`。

**门锁收到 `0x6C` 后立即回空 `0xEC`**，避免背板重传。

### 2.4 `0x6E` 联动开锁执行（背板 → 门锁）

| 字段 | 说明 |
|---|---|
| payload | 无（空包） |
| 应答 | `0xEE`（空包），门锁**先应答再开锁** |

门锁处理顺序：

1. 收到 `0x6E` 立即回 `0xEE`；
2. 按 `sn` 去重：同一帧的重发（sn 相同）只执行一次开锁；
3. 记录一条"场景联动开锁"开锁记录；
4. 前板执行开锁（电机开锁 + 绿灯提示）。

> **没有回 `0xEE` 时背板要重发**（沿用通用重传规则）：同一 `sn` 重发，门锁只应答并跳过重复执行。
> 门锁在管理员菜单等交互过程中收到 `0x6E` 只应答不执行，避免打断本地操作。
> **恢复出厂设置时门锁会主动下发一次 `0x6D`（退出联动，不等应答）**：背板需清理配对关系，回 `0xED` 即可，门锁此时已不在配对流程中，收到 `0xED` 只丢弃。

## 3. 背板侧要做的

1. 收到 `0x6A`（创建）或 `0x6B`（加入）：
   - 校验 payload 长度为 4、每字节在 `0~9` 范围内
   - 记录本机角色（收到 `0x6A` = 创建方 role 0，收到 `0x6B` = 加入方 role 1）与 PIN
   - **立即**回 `0xEA` / `0xEB`（status `0`=正常；`1`=异常）
2. 收到 `0x6D`（退出）：
   - 校验本机是否处于已配对状态（未配对就退出 → status 非 0）
   - **立即**回 `0xED`（status `0`=正常；`1`=异常）
   - 通知对端背板解除配对
   - 完成后上报 `0x6C`（`role=2, result=0`）给本端前板
3. 两台背板在服务端完成 PIN 匹配：
   - **B 锁的背板**：加入成功 → 上报 `0x6C`（`role=1, result=0`）给 B 锁前板
   - **A 锁的背板**：感知 B 已加入 → 上报 `0x6C`（`role=0, result=0`）给 A 锁前板
4. 任何场景失败（PIN 不一致、超时、服务端拒绝、未配对就退出）都要上报 `0x6C`（对应 role，`result=1`），不能让门锁干等

### 3.1 ⚠️ 必须保证幂等

门锁对 `0x6A`/`0x6B`/`0x6D` 按通用规则**重传 2 次**（300ms 间隔），背板可能重复收到：

- 重复的 `0x6A`/`0x6B`/`0x6D`：**仍回 status `0`**，不要因"已在处理中"而回失败，否则门锁会误判失败
- 重复的 `0x6C`：门锁只按 `role` 匹配当前流程，重复包只会重复应答 `0xEC`，不会重复播报（门锁收到第一包后即结束等待）

## 4. 时序

### 4.1 A 锁（创建方）

```
创建联动菜单 → 输入 4 位 PIN + #
  → 0x6A（PIN）
       ├─ 300ms 未回 → 重传（最多 2 次）
       └─ 背板回 0xEA(status=0) → 播"配对中请稍候"，等待 B 锁加入（最长 60s）
              └─ 背板回 0x6C(role=0, result=0)
                    → 门锁回 0xEC → 播"设置成功" → 回"更多设置"
```

### 4.2 B 锁（加入方）

```
加入联动菜单 → 输入同一 4 位 PIN + #
  → 0x6B（PIN）
       ├─ 300ms 未回 → 重传（最多 2 次）
       └─ 背板回 0xEB(status=0) → 播"配对中请稍候"，等待配对结果（最长 60s）
              └─ 背板回 0x6C(role=1, result=0)
                    → 门锁回 0xEC → 播"设置成功" → 回"更多设置"
```

### 4.3 两锁合并时序

```
A 锁:  0x6A ──────────▶ 背板A   （回 0xEA）
B 锁:  0x6B ──────────▶ 背板B   （回 0xEB）
                     背板A ⇄ 背板B  服务端按 PIN 配对
背板B ── 0x6C(role=1,result=0) ──▶ B 锁   （B 回 0xEC，播"设置成功"）
背板A ── 0x6C(role=0,result=0) ──▶ A 锁   （A 回 0xEC，播"设置成功"）
```

### 4.4 退出联动（任意一锁）

```
退出联动菜单 → 按 OK 确认
  → 0x6D（空包）
       ├─ 300ms 未回 → 重传（最多 2 次）
       └─ 背板回 0xED(status=0) → 播"配对中请稍候"，等待退出结果（最长 60s）
              └─ 背板回 0x6C(role=2, result=0)
                    → 门锁回 0xEC → 播"设置成功" → 回"更多设置"
```

## 5. 异常处理

| 情况 | 门锁行为 |
|---|---|
| 1 秒内无 `0xEA`/`0xEB`/`0xED` | 播"设置失败"（红灯闪 4 次），退出流程 |
| `0xEA`/`0xEB`/`0xED` 空包或 status≠0 | 播"设置失败"，退出流程 |
| 收到 `0x6C` 但 `role` 与当前流程不符 | 只回 `0xEC`，不改界面（防迟到包/串包） |
| `0x6C` 的 `result`≠0 | 播"设置失败"，退出流程 |
| 60 秒仍无 `0x6C` | 播"操作超时"，退出流程（背板仍在处理则结果包会被丢弃） |
| 等待期间用户按键 | 门锁不响应键盘（避免重复下发），超时/成功后才恢复 |
| 退出菜单后才收到 `0x6C` | 只回 `0xEC`，不改界面 |

## 6. 联调验证

| 观察点 | 期望 |
|---|---|
| A 锁日志 | `[uart tx] cmd=0x6A, len[4]`（payload 为 4 位 PIN 的数字值） |
| A 锁日志 | `[uart rx] cmd=0xEA, len=1`（status=0） |
| B 锁日志 | `[uart tx] cmd=0x6B, len[4]` |
| B 锁日志 | `[uart rx] cmd=0xEB, len=1`（status=0） |
| B 锁日志 | `[uart rx] cmd=0x6C, len=2`，`role=1, result=0` → 播"设置成功" |
| A 锁日志 | `[uart rx] cmd=0x6C, len=2`，`role=0, result=0` → 播"设置成功" |
| **退出日志** | `[uart tx] cmd=0x6D, len[0]` → 收到 `0xED, len=1`(status=0) → `0x6C role=2, result=0` → 播"设置成功" |
| **联动开锁日志** | `[uart rx] cmd=0x6E, len=0` → 门锁回 `0xEE` → 电机开锁 + 绿灯；重发同一 sn 只有一条开锁记录 |
| 背板日志 | 每次 `0x6C` 都收到门锁的 `0xEC` |

**验收标准**：
1. A 输 PIN 后提示"配对中请稍候"，B 输入相同 PIN 后两台锁都在 60s 内播"设置成功"；
2. PIN 不一致 / 背板回 status≠0 / 无应答时，两台锁都能在超时内提示"设置失败"或"操作超时"，不卡死；
3. A、B 锁为同一固件，互换角色（A 做加入、B 做创建）同样可用；
4. 任意一台锁退出联动后，60s 内播"设置成功"，配对关系正确解除。

---

## 7. 注意

- PIN 传输是**数字 0~9**（每字节一个数字），不是 ASCII 字符串，也不是整型压缩；
- `0x6C` 的 `role` 由**背板**填写，门锁不会自己推断；门锁只接受与当前流程（创建=0 / 加入=1 / 退出=2）一致的包；
- 门锁侧超时：ACK 1s、整体等待 60s（退出也共用该值），均由门锁自己兜底，背板不需要额外超时提示；
- 本流程不写本地用户数据，配对关系由背板/服务端维护；
- **退出命令无 payload**，门锁角色由背板内部状态（已配对与否）决定，不需要门锁额外告知。
