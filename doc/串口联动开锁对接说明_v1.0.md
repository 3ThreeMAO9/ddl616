# 门锁 ↔ WiFi 模块 联动开锁（4 位配对码）对接说明

**版本**：v1.0（2026-11-05）　**门锁侧已实现，等 WiFi/背板适配**

---

## 1. 用途

两台门锁（A 锁、B 锁）通过各自的 WiFi 模块（下称背板）完成"联动开锁"配对：

- **A 锁**进入"创建联动"菜单 → 输入 **4 位 PIN 码** → 下发 `0x6A` 给背板 → 背板回 `0xEA`（指令接收是否正常）→ A 锁等待 B 锁加入
- **B 锁**进入"加入联动"菜单 → 输入 **与 A 锁相同**的 4 位 PIN 码 → 下发 `0x6B` 给背板 → 背板回 `0xEB`（指令接收是否正常）→ B 锁等待配对结果
- B 加入成功 → **B 的背板上报 `0x6C`（role=1）给 B 锁前板** → B 锁播"设置成功"
- A 的背板感知 B 加入成功 → **A 的背板上报 `0x6C`（role=0）给 A 锁前板** → A 锁播"设置成功"

> A 锁、B 锁烧录的是**同一套固件**，不区分主从；角色只由"用户进了哪个菜单"决定，协议里用 `role` 字段告知背板。

---

## 2. 命令定义

| 命令 | 方向 | payload | 应答 |
|---|---|---|---|
| **`0x6A`** 创建联动 | **门锁 → 背板** | 4 字节 PIN（见 2.1） | **`0xEA`** + 1 字节 status |
| **`0x6B`** 加入联动 | **门锁 → 背板** | 4 字节 PIN（见 2.1） | **`0xEB`** + 1 字节 status |
| **`0x6C`** 配对结果上报 | **背板 → 门锁** | 2 字节：`role` + `result`（见 2.3） | **`0x6C` 的 ACK = `0xEC`**（空包） |

> ACK 命令字沿用通用规则：`ACK = 命令字 | 0x80`。
> 所有命令 `enc=1`，`key = random ^ K_L`（与其它串口命令一致）。

### 2.1 `0x6A` / `0x6B` payload

| 偏移 | 长度 | 内容 | 说明 |
|---|---|---|---|
| 0 | 4 | PIN 码 | 每字节 **0~9**（数字值，**不是 ASCII `'0'~'9'`**） |

示例：PIN `1234` → `01 02 03 04`

### 2.2 `0xEA` / `0xEB` payload（指令接收正常与否）

| 值 | 含义 | 门锁行为 |
|---|---|---|
| `0x00` | 指令接收正常，已开始配对 | 继续等待 `0x6C`（界面播"配对中请稍候"） |
| 其它 / 空包 | 指令异常（PIN 格式错、已在配对中、无网络…） | 立即播"设置失败"，退出流程 |

> **背板收到 `0x6A`/`0x6B` 后必须立刻回 `0xEA`/`0xEB`**；不回 = 门锁 1 秒后判失败。

### 2.3 `0x6C` payload（配对结果上报）

| 偏移 | 字段 | 取值 |
|---|---|---|
| 0 | `role` | `0`=创建方（A 锁）；`1`=加入方（B 锁） |
| 1 | `result` | `0`=成功；`1`=失败 |

示例：A 锁创建成功 → `00 00`；B 锁加入成功 → `01 00`。

**门锁收到 `0x6C` 后立即回空 `0xEC`**，避免背板重传。

---

## 3. 背板侧要做的

1. 收到 `0x6A`（创建）或 `0x6B`（加入）：
   - 校验 payload 长度为 4、每字节在 `0~9` 范围内
   - 记录本机角色（收到 `0x6A` = 创建方 role 0，收到 `0x6B` = 加入方 role 1）与 PIN
   - **立即**回 `0xEA` / `0xEB`（status `0`=正常；`1`=异常）
2. 两台背板在服务端完成 PIN 匹配：
   - **B 锁的背板**：加入成功 → 上报 `0x6C`（`role=1, result=0`）给 B 锁前板
   - **A 锁的背板**：感知 B 已加入 → 上报 `0x6C`（`role=0, result=0`）给 A 锁前板
3. 配对失败（PIN 不一致、超时、服务端拒绝）也要上报 `0x6C`（对应 role，`result=1`），不能让门锁干等

### 3.1 ⚠️ 必须保证幂等

门锁对 `0x6A`/`0x6B` 按通用规则**重传 2 次**（300ms 间隔），背板可能重复收到：

- 重复的 `0x6A`/`0x6B`：**仍回 status `0`**，不要因"已在配对中"而回失败，否则门锁会误判失败
- 重复的 `0x6C`：门锁只按 `role` 匹配当前流程，重复包只会重复应答 `0xEC`，不会重复播报（门锁收到第一包后即结束等待）

## 4. 时序

### 4.1 A 锁（创建方）

```
创建联动菜单 → 输入 4 位 PIN + #
  → 0x6A（PIN）
       ├─ 300ms 未回 → 重传（最多 2 次）
       └─ 背板回 0xEA(status=0) → 播"配对中请稍候"，等待 B 锁加入（最长 60s）
              └─ 背板回 0x6C(role=0, result=0)
                    → 门锁回 0xEC → 播"设置成功" → 回"更多设置"
```

### 4.2 B 锁（加入方）

```
加入联动菜单 → 输入同一 4 位 PIN + #
  → 0x6B（PIN）
       ├─ 300ms 未回 → 重传（最多 2 次）
       └─ 背板回 0xEB(status=0) → 播"配对中请稍候"，等待配对结果（最长 60s）
              └─ 背板回 0x6C(role=1, result=0)
                    → 门锁回 0xEC → 播"设置成功" → 回"更多设置"
```

### 4.3 两锁合并时序

```
A 锁:  0x6A ──────────▶ 背板A   （回 0xEA）
B 锁:  0x6B ──────────▶ 背板B   （回 0xEB）
                     背板A ⇄ 背板B  服务端按 PIN 配对
背板B ── 0x6C(role=1,result=0) ──▶ B 锁   （B 回 0xEC，播"设置成功"）
背板A ── 0x6C(role=0,result=0) ──▶ A 锁   （A 回 0xEC，播"设置成功"）
```

---

## 5. 异常处理

| 情况 | 门锁行为 |
|---|---|
| 1 秒内无 `0xEA`/`0xEB` | 播"设置失败"（红灯闪 4 次），退出流程 |
| `0xEA`/`0xEB` 空包或 status≠0 | 播"设置失败"，退出流程 |
| 收到 `0x6C` 但 `role` 与当前流程不符 | 只回 `0xEC`，不改界面（防迟到包/串包） |
| `0x6C` 的 `result`≠0 | 播"设置失败"，退出流程 |
| 60 秒仍无 `0x6C` | 播"操作超时"，退出流程（背板仍在配对则结果包会被丢弃） |
| 等待期间用户按键 | 门锁不响应键盘（避免重复下发），超时/成功后才恢复 |
| 退出菜单后才收到 `0x6C` | 只回 `0xEC`，不改界面 |

## 6. 联调验证

| 观察点 | 期望 |
|---|---|
| A 锁日志 | `[uart tx] cmd=0x6A, len[4]`（payload 为 4 位 PIN 的数字值） |
| A 锁日志 | `[uart rx] cmd=0xEA, len=1`（status=0） |
| B 锁日志 | `[uart tx] cmd=0x6B, len[4]` |
| B 锁日志 | `[uart rx] cmd=0xEB, len=1`（status=0） |
| B 锁日志 | `[uart rx] cmd=0x6C, len=2`，`role=1, result=0` → 播"设置成功" |
| A 锁日志 | `[uart rx] cmd=0x6C, len=2`，`role=0, result=0` → 播"设置成功" |
| 背板日志 | 收到 `0xEC`（A、B 各一次） |

**验收标准**：
1. A 输 PIN 后提示"配对中请稍候"，B 输入相同 PIN 后两台锁都在 60s 内播"设置成功"；
2. PIN 不一致 / 背板回 status≠0 / 无应答时，两台锁都能在超时内提示"设置失败"或"操作超时"，不卡死；
3. A、B 锁为同一固件，互换角色（A 做加入、B 做创建）同样可用。

---

## 7. 注意

- PIN 传输是**数字 0~9**（每字节一个数字），不是 ASCII 字符串，也不是整型压缩；
- `0x6C` 的 `role` 由**背板**填写，门锁不会自己推断；门锁只接受与当前流程（创建=0 / 加入=1）一致的包；
- 门锁侧超时：ACK 1s、整体等待（含对方加入）60s，均由门锁自己兜底，背板不需要额外超时提示；
- 本流程不写本地用户数据，配对关系由背板/服务端维护。
