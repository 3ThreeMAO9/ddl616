# 串口 OTA 升级对接说明 v1.2

适用固件：门锁 app `V39.140.005` 及以后
协议实现：`application/protocol/handler/uart_protocol_ota.c`

## v1.2 相对 v1.1 的变更

| 项目 | v1.1 | v1.2 |
|---|---|---|
| 单包数据长度 | 240 | **200**（`OTA_PKT_SIZE`） |
| 成功结果上报时机 | 下载结束、重启前 | **boot 搬运完成、新 app 启动后** |
| `0xF3` status | 0/1/2 | 增加 **3 = 写后回读失败** |
| 镜像头 / `0x74` version | 镜像头固定 0.0.1 | **真实版本**（打包时写入，与 `0x74` 编码一致） |
| `0x74` 加密 | 未说明 | 明确为**会话密钥加密**，模组须先应答 `0x70` |
| OTA 区地址 | 固定容量末尾 64K | 语音包头声明优先，未声明才退回末尾 64K |

## 总体流程

```
模组 ──0x72 开始（size/checksum/version）──> 门锁
     <──0xF2 应答（status + pkt_size=200）──          门锁擦除 64K，1~2 秒
模组 ──0x73 数据（offset + N 字节）──> 门锁
     <──0xF3 应答（status + expected）──              重复 N 次，逐包写 flash + 回读
模组 ──0x73 结束（offset + 0 字节）──> 门锁
     <──0xF3 应答（status + expected）──              校验长度/累加和/镜像头

  ┌ 失败：紧接上报 0x74（result=1/2），结束
  └ 成功：门锁置 ota_info=WAIT，200ms 后跳 boot，搬运约 6 秒
           <──0x70 密钥（新 app 启动后主动发）──     模组回 0xF0
           <──0x74 结果（result=0 + 新版本）──        模组回 0xF4
```

> 成功路径的 `0x74` **不是紧接着结束包发出的**，而是设备重启、boot 搬运完成、新 app 启动后才上报。
> 模组在收到结束包的 `0xF3` 后应继续等待，超时建议 ≥ 30 秒。

## 1. 帧格式

复用门锁串口协议（`uart_packet.h`）：

```
A5 | attr | checksum1(2) | sn(2) | cmd | random | checksum2(2) | length(2) | payload
```

- 12 字节头，`length` 为 payload 字节数（uint16）
- 单帧受 `UART0_BUF_LEN = 256` 限制，**payload ≤ 244**
- 应答命令字 = `cmd | 0x80`
- 重传由 `sn` + ACK 保证

**加密约定**：

- 下载方向（`0x72`/`0x73`）：**明文**，`attr` 加密位 = 0，`random` = 0；
- 上报方向（`0x74`）：走门锁通用加密（XOR，密钥为当前会话密钥）。模组必须在设备重启后先应答 `0x70` 取得新密钥，才能正确解析 `0x74`。

## 2. 命令字

| 命令 | 方向 | 说明 |
|---|---|---|
| `0x72` | 模组 → 门锁 | 升级开始 |
| `0xF2` | 门锁 → 模组 | 升级开始应答 |
| `0x73` | 模组 → 门锁 | 数据包 / 结束包 |
| `0xF3` | 门锁 → 模组 | 数据应答 |
| `0x74` | 门锁 → 模组 | 升级结果（加密） |
| `0xF4` | 模组 → 门锁 | 结果应答 |

## 3. payload 定义（多字节小端）

### 3.1 `0x72` 升级开始

```
[size 4B][checksum 4B][version 3B]          共 11 字节
```

| 字段 | 说明 |
|---|---|
| `size` | 固件数据段长度，**不含 16 字节文件头**；合法范围 4 ~ 63488 |
| `checksum` | 数据段 32 位累加和（4 字节一组小端累加，尾部补零） |
| `version` | 版本 X.Y.Z，结束包时与镜像头版本比对 |

**应答 `0xF2`**：`[status 1B][pkt_size 2B]`

| status | 含义 | 对端动作 |
|---|---|---|
| 0 | 就绪 | 按 `pkt_size` 发数据 |
| 1 | 长度超限 / flash 不可用 | 中止 |
| 2 | 忙（已在升级） | 稍后重试 |
| 3 | 版本与设备相同 | 结束，无需升级 |
| 4 | OTA 区擦除失败（写保护/硬件异常） | 中止，检查 flash 写保护 |

`pkt_size` 当前固定 **200**。

> 收到 `0x72` 后门锁清写保护并擦除 64K OTA 区，耗时 1~2 秒。
> **等待 `0xF2` 的超时应 ≥ 5 秒**，期间不要重发 `0x72`。

### 3.2 `0x73` 数据包 / 结束包

```
[offset 4B][data N]                        N ≤ 244，建议 200（4 的倍数）
```

- `N > 0`：数据包，`offset` 为本包在固件中的偏移（从 0 开始）
- `N == 0`：**结束包**，表示固件已全部发送

**应答 `0xF3`**：`[status 1B][expected 4B]`

| status | 含义 | 对端动作 |
|---|---|---|
| 0 | 写入成功 / 重复包已忽略 / 结束包校验通过 | 继续或结束 |
| 1 | 偏移不连续 | 按应答的 `expected` 续传 |
| 2 | 写 flash 失败 | 重发本包，连续失败则中止 |
| 3 | 写后回读不一致 | 中止，重新开始 |
| 4 | 没有进行中的升级（未发 `0x72` 或已结束） | 重新发 `0x72` |

规则：

- 门锁维护 `expected_offset`，正常只写 `offset == expected_offset` 的包；
- `offset < expected` 且整包已写过 → 视为重传，回 status=0，**不重复写**（NOR 不能重复编程）；
- 部分重叠（`offset < expected` 但尾部超出）→ 只写超出部分；
- `offset > expected` → status=1，`expected` 字段回填当前期望偏移。

**结束包处理**（顺序）：

1. 收到的总字节数必须等于 `size`，否则 `0x74` result=2；
2. 本地累加和必须等于 `0x72` 下发的 `checksum`，否则 `0x74` result=1；
3. 回读镜像头（magic/size/checksum/version）与本次下发一致，否则 `0x74` result=1；
4. 全部通过 → `0xF3` status=0，置 `ota_info=WAIT`，200ms 后跳 boot，**此时不报 `0x74`**。

### 3.3 `0x74` 升级结果（门锁 → 模组，加密）

```
[result 1B][version 3B]                    共 4 字节
```

`version` 编码（与镜像头 `version` 字段一致）：

```
[sn/1000][sn%1000][PATCH_VERSION]
例：sn=39140、PATCH=5  →  version = [39][140][05]
    0x74 完整 payload  = [00][39][140][05]（result=0 + version）
```

| result | 含义 | 上报时机 |
|---|---|---|
| 0 | 升级成功，版本已切换 | **设备重启、boot 搬运完成后**（约 6 秒） |
| 1 | 校验和 / 镜像头 / 回读失败 | 结束包后立即，或重启后由 app 上报 |
| 2 | 收到的字节数不符 | 结束包后立即 |
| 3 | boot 备份失败，未执行搬运（仍在旧固件） | 重启后由 app 上报 |

模组收到 `0x74` 后应回 `0xF4`。门锁未收到应答会重传（最多 2 次、间隔 300ms），
之后放弃，因此设备重启后模组必须及时就绪。

**判据**：以 `0x74` 的 result 为准，不要仅凭"设备离线/上线"判断成功。

## 4. 超时建议

| 等待项 | 建议超时 | 说明 |
|---|---|---|
| `0xF2` | ≥ 5 s | 含 64K 擦除 |
| `0xF3`（数据包） | ≥ 1 s | 含 flash 写 + 回读 |
| `0xF3`（结束包） | ≥ 5 s | 含镜像头回读 |
| `0x74`（失败路径） | ≥ 3 s | 紧接结束包 |
| `0x74`（成功路径） | ≥ 30 s | 含重启 + boot 搬运（约 6 s）+ 密钥协商 |

## 5. 约束与说明

1. **升级期间**：重复 `0x72` 回 status=2；擦除和逐包写 flash 会占用主循环，其它业务命令的应答会明显延迟，建议升级期间不发送其它命令。
2. **掉电保护**：只有结束包校验通过才写 `ota_info=WAIT`，中途掉电不会触发 boot 搬运，设备继续运行旧 app。
3. **包长与速率**：当前每包 200 字节，63 KB 固件约 318 包，230400 bps 下下载约 9~10 秒（不含擦除和 boot 搬运）。
4. **OTA 区地址**：优先取语音包头声明的 OTA 域（域起始 + 域大小/2），未声明时退回 SPI flash 容量末尾 64K，与 boot 的 `SFLASH_OTA_BEGIN_ADDR` 保持一致。
5. **版本判断**：升级成功后设备重启，`0x74` 携带的就是新固件编译进去的版本，可直接用于校验版本是否翻转。

## 6. 对接参考脚本（tools/ota_host）

联调时可直接使用仓库自带的上位机脚本，无需自己从头实现协议：

| 文件 | 用途 |
|---|---|
| `tools/ota_host/ota_proto.py` | 协议完整实现（约 600 行，仅依赖 pyserial）：密钥协商、0x72/0x73 全流程、断点续传、0x74 处理、自动 ACK 设备侧请求。模组侧实现可对照它逐帧核对 |
| `tools/ota_host/ota_gui.py` | 图形界面：单次/循环升级、进度统计、日志勾选 |
| `tools/ota_host/ota_gui.bat` | 双击启动 GUI（pythonw，无控制台） |
| `tools/ota_host/log/` | 每次升级的完整日志（含每帧原始 TX/RX hex） |

GUI 勾选框说明：**串口数据**=显示每帧原始收发字节（大写 hex）+ 解码摘要；**门锁日志**=显示门锁 `[dev]` 调试行（FSM、擦写失败现场等）。循环升级的所有轮次写入同一个日志文件。

模组侧实现必须满足（从脚本行为反推的对接要点）：

1. **0x70 密钥帧必须回 0xF0**：升级结束后的 `0x74` 用会话密钥加密，模组不更新密钥就解不开结果帧；
2. **0xF3 status≠0 时按应答里的 offset 续传**：脚本收到 status=1 会自动从该偏移重发，模组侧同样要处理；
3. **收到 0x74 必须回 0xF4 回执**：否则门锁会按 300ms 间隔重传 2 次；
4. **升级期间设备可能主动发 0x67 时间查询、0x70 密钥帧**：脚本会自动 ACK，模组侧也要具备同等处理能力，否则设备会重传到超时；
5. **0xF2 status=3（版本相同）**：表示设备已是目标版本，视为本次"跳过"，不应按失败重试；
6. **每包等待 0xF3 超时建议 ≥ 1 秒**，重发时先回退到 0xF3 应答的 offset 再续传（脚本在连续 2 次无应答后会回退）。
