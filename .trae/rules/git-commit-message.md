# 提交信息规则

根据本仓库历史提交（`git log`）归纳，生成提交信息时遵守以下约定。

## 格式

```
[NNN]动词开头的简短描述
```

- `NNN` 为三位数字，表示当前开发批次/任务号；默认沿用最近一次提交的编号（当前为 `[005]`），用户明确要求时才递增。
- 方括号与描述之间不加空格，例如：`[003]增加管理指纹`。
- 单行中文标题，建议不超过 30 字，结尾不加句号。
- 正文默认留空；确有必要时再补简短正文，说明关键改动或验证方式。

## 描述写法

1. 以动词开头：增加、实现、新增、优化、调整、修复、移除、删除、精简、完善、更新、裁剪、关闭、正确……。
2. 写清"做了什么 + 涉及的模块/命令字/现象"，避免"修改代码""更新代码"这类无信息量描述。
3. 同一次提交有多个相关改动时用"并"连接，最多两三个要点，不写流水账。例如：`[003]新增TOTP协议并优化串口收发日志与解密时序`。
4. 修复类要带上现象或根因。例如：`[003]修复休眠状态下APP发起指纹卡片录入无响应的问题`。
5. 专有名词保持原写法：OTA、boot、app、SPI Flash、Keil、TOTP、HAL 等；命令字写成 `0x74` 形式。
6. 标题内不用 emoji，不写英文整句，不加 `commit:` 之类前缀。

## 编号语义（参考）

- `[001]` 基础功能与驱动
- `[003]` 串口协议、菜单与配网交互
- `[004]` 人脸、语音相关
- `[005]` OTA 升级

批次号在同一开发阶段内保持不变，不按提交次数递增。

## 示例（本仓库真实提交）

- `[003]增加管理指纹`
- `[003]移除蓝牙版本协议并补全蓝牙MAC获取重试机制`
- `[005]增加ota上位机`
- `[005]精简OTA回读校验逻辑并移除冗余状态输出`
